# STM32F4 球平衡/智能小车项目说明文档

## 1. 项目总体概览

本项目是基于 STM32F4 系列单片机的嵌入式控制工程，工程来源带有 WHEELTEC 智能车/平衡车代码框架特征。当前代码使用 Keil MDK 工程组织，底层基于 STM32F4 标准外设库，任务调度使用 FreeRTOS。

从现有文件和代码看，项目主要面向一类带编码器、电机、舵机、IMU、OLED、PS2 手柄、串口/蓝牙/雷达等外设的智能小车控制系统。核心功能包括：

- 系统硬件初始化。
- FreeRTOS 多任务调度。
- 电机 PWM 输出。
- 编码器速度采集。
- 电池电压 ADC 采样。
- OLED 显示。
- 蜂鸣器与 LED 状态提示。
- PS2 手柄控制。
- 串口通信和部分雷达数据结构支持。
- IMU 型号自动识别，支持 MPU6050 和 ICM20948 两类硬件版本。
- 小车模型参数选择，支持麦克纳姆轮、全向轮、阿克曼、差速、四轮、履带等模式的通用框架。

需要注意：部分源文件存在中文注释编码异常，是 GBK/ANSI 文件在 UTF-8 环境中显示导致。

## 3. 程序启动与任务调度流程

### 3.1 启动链路

典型执行流程如下：

1. 芯片复位后从启动文件进入 C 运行环境。
2. 调用 `main()`。
3. `main()` 调用 `systemInit()` 完成硬件初始化。
4. `main()` 创建 `start_task`。
5. 调用 `vTaskStartScheduler()` 启动 FreeRTOS 调度器。
6. `start_task` 创建实际业务任务。
7. `start_task` 删除自身。

### 3.2 `main()` 关键逻辑

`USER/main.c` 中：

- `systemInit()`：硬件初始化总入口。
- `xTaskCreate(start_task, ...)`：创建启动任务。
- `vTaskStartScheduler()`：启动 RTOS。

`start_task()` 创建以下任务：

| 任务函数 | 任务名 | 作用 | 优先级来源 | 栈大小来源 |
|---|---|---|---|---|
| `Balance_task` | `Balance_task` | 小车运动控制任务 | `BALANCE_TASK_PRIO` | `BALANCE_STK_SIZE` |
| `show_task` | `show_task` | OLED 显示、APP 上报、电压报警 | `SHOW_TASK_PRIO` | `SHOW_STK_SIZE` |
| `led_task` | `led_task` | LED 闪烁状态提示 | `LED_TASK_PRIO` | `LED_STK_SIZE` |
| `pstwo_task` | `PSTWO_task` | PS2 手柄读取 | `PS2_TASK_PRIO` | `PS2_STK_SIZE` |
| `adc_task` | `ADC_task` | ADC 采样，CCD/ELE 数据处理 | `ADC_TASK_PRIO` | `ADC_STK_SIZE` |

## 4. 系统初始化说明

系统初始化总入口是 `systemInit()`，位于 `BALANCE/system.c`。

主要初始化顺序：

1. `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_4)`：设置中断优先级分组。
2. `delay_init(168)`：初始化延时系统，按 168MHz 主频配置。
3. `I2C_GPIOInit()`：初始化 IMU 使用的 I2C 引脚。
4. `SYS_VAL_t_Init(&SysVal)`：初始化系统运行状态结构体。
5. `uart1_init(115200)`：USART1 初始化，常用于 ROS/上位机通信。
6. `uart2_init(9600)`：USART2 初始化，常用于蓝牙 APP。
7. `uart5_init(460800)`：UART5 初始化，可能用于高速通信或雷达/上位机。
8. 读取 IMU ID：
   - 若识别为 MPU6050，则设置硬件版本 `V1_0`，初始化 PS2 和旧版 LED。
   - 若识别为 ICM20948，则设置硬件版本 `V1_1`，初始化 USB Host 和新版 LED。
   - 如果无法识别，则 `NVIC_SystemReset()` 复位系统。
9. `Buzzer_Init()`：蜂鸣器初始化。
10. `Enable_Pin()`：电机使能开关引脚初始化。
11. `OLED_Init()`：OLED 初始化。
12. `KEY_Init()`：按键初始化。
13. `Adc_Init()` / `Adc_POWER_Init()`：ADC 初始化。
14. `Robot_Select()`：根据电位器档位选择小车型号并初始化参数。
15. `TIM8_SERVO_Init(9999,168-1)`：舵机 PWM，约 100Hz。
16. `TIM1_PWM_Init(16799,0)`、`TIM9_PWM_Init(16799,0)`、`TIM10_PWM_Init(16799,0)`、`TIM11_PWM_Init(16799,0)`：电机 PWM 初始化，约 10kHz。
17. `Encoder_Init_TIM2()`、`Encoder_Init_TIM3()`、`Encoder_Init_TIM4()`、`Encoder_Init_TIM5()`：四路编码器初始化。

### 5.2 `control.c` 中的关键函数

#### `Kinematic_Analysis(float Vy, float angle)`

作用：将遥控输入的纵向速度 `Vy` 和转向角 `angle` 转换为左右轮目标速度与舵机 PWM。

核心计算：

- `Target_A = Vy * (1 + T * tan(angle) / 2 / L)`
- `Target_B = Vy * (1 - T * tan(angle) / 2 / L)`
- `Servo = SERVO_INIT - angle * K`

这更接近阿克曼/舵机转向小车的运动学分配逻辑。

#### `EXTI15_10_IRQHandler(void)`

作用：外部中断处理函数，代码注释说明为由 MPU6050 INT 引脚触发，控制周期约 5ms/10ms。

主要工作：

- 清除外部中断标志。
- 交替读取 IMU 姿态与编码器速度。
- 扫描按键。
- 读取编码器：`Read_Encoder(2)`、`Read_Encoder(3)`。
- 累计编码器积分位置。
- 读取 DMP 姿态：`Read_DMP()`。
- LED 闪烁。
- 采集电池电压。
- 判断 PS2/CAN/串口控制模式。
- 执行遥控解析：`Get_RC()` 或 `CAN_N_Usart_Control()`。
- 电压正常时执行速度 PI 控制：`Incremental_PI_A()` / `Incremental_PI_B()`。
- 执行 PWM 限幅：`Xianfu_Pwm(6900)`。
- 输出 PWM：`Set_Pwm()`。
- 电压异常时关闭电机输出。

#### `Set_Pwm(int motor_a, int motor_b, int servo)`

作用：根据 PWM 正负决定电机方向，并写入 PWM 比较寄存器，同时更新舵机 PWM。

注意：当前 `control.c` 版本只控制 A/B 两个电机和舵机；而 `balance.h` 中声明了四电机版本 `Set_Pwm(int motor_a,int motor_b,int motor_c,int motor_d,int servo)`，说明工程中可能存在多车型通用代码和当前裁剪代码的差异。

#### `Xianfu_Pwm(int amplitude)`

作用：电机 PWM 限幅，保护电机和驱动器。

- `Motor_A`、`Motor_B` 被限制在 `[-amplitude, amplitude]`。
- 舵机 `Servo` 上限限制为 1930。

#### `Turn_Off(int voltage)`

作用：低电压保护。

- 当 `voltage < 1110` 时，关闭 `PWMA` 和 `PWMB`，返回异常状态。
- 否则返回正常状态。

从 `adc.c` 看，电池电压函数返回单位更像 V；而这里用 `1110`，可能是旧代码遗留或单位不一致，后续调试时应重点确认 `Voltage` 的实际单位。

#### `Incremental_PI_A()` / `Incremental_PI_B()`

作用：增量式 PI 速度闭环控制。

核心公式：

`Pwm += Velocity_KP * (Bias - Last_bias) + Velocity_KI * Bias`

其中：

- `Bias = Encoder - Target`
- 输出限幅在 `[-7200, 7200]`

#### `Get_RC(u8 mode)`

作用：根据遥控方向标志 `Flag_Direction` 生成 `Move_Y` 和 `Angle`，随后调用 `Kinematic_Analysis()` 得到目标速度。

#### `CAN_N_Usart_Control(void)`

作用：解析 CAN/串口/PS2 控制输入。

- CAN/串口模式：从 `rxbuf` 中解析速度方向和角度。
- PS2 模式：读取 `PS2_RX` 和 `PS2_LY`，设定死区 `Yuzhi=20`，转换为 `Angle` 和 `Move_Y`。
- 最后统一调用 `Kinematic_Analysis()`。

### 6.2 舵机 PWM

文件：`HARDWARE/timer.c`、`HARDWARE/timer.h`

`TIM8_SERVO_Init(9999,168-1)` 初始化 TIM8_CH4，输出脚 PC9。

- 频率约 100Hz。
- `SERVO_INIT = 1500` 为舵机中位。
- 舵机 PWM 寄存器宏：`Servo_PWM` 或部分控制代码中的 `SERVO`。

### 6.7 PS2 手柄

文件：`HARDWARE/pstwo.c`、`HARDWARE/pstwo.h`

PS2 相关引脚：

| 信号 | 宏 | 引脚 |
|---|---|---|
| DI | `DI` | PE15 |
| DO | `DO_H` / `DO_L` | PE12 |
| CS | `CS_H` / `CS_L` | PE10 |
| CLK | `CLK_H` / `CLK_L` | PE8 |

关键函数：

- `PS2_Init()`：GPIO 初始化。
- `PS2_SetInit()`：配置手柄为模拟模式。
- `PS2_ReadData()`：读取原始数据。
- `PS2_DataKey()`：读取按键。
- `PS2_AnologData()`：读取摇杆模拟量。
- `PS2_Receive()`：业务接收入口。

### 6.8 串口与雷达数据

文件：`HARDWARE/usartx.c`、`HARDWARE/usartx.h`

提供：

- `uart1_init()`：USART1。
- `uart2_init()`：USART2。
- `uart5_init()`：UART5。
- `USART1_IRQHandler()`、`USART2_IRQHandler()`、`UART5_IRQHandler()`：串口中断入口。
- `usart1_send()`、`usart2_send()`、`usart5_send()`：单字节发送。
- `data_process()`：数据处理入口。

`usartx.h` 中还定义了激光雷达帧结构：

- 帧头 `0xA5 0x5A`。
- 每包 32 个点。
- 每个点包含距离高低字节和强度。
- `PointDataProcess[1200]` 和 `Dataprocess[1200]` 存储解析后点云。

这说明工程预留了雷达避障、跟随、沿墙等模式的数据接口。

### 6.9 IMU

## 11. 目前代码中值得关注的问题

### 11.1 文件编码问题

部分 `.c` 文件被读取工具识别为二进制，如：

- `BALANCE/balance.c`
- `BALANCE/filter.c`
- `BALANCE/robot_select_init.c`
- `HARDWARE/usartx.c`

这通常不是代码不可用，而是编码或文件中存在特殊字节导致。建议：

1. 用 Keil 打开确认是否正常。
2. 若在 VS Code 中开发，尝试以 GBK/GB2312 编码重新打开。
3. 后续统一转 UTF-8 前，先确认 Keil 编译链是否受影响。

### 11.2 控制接口版本不一致

`BALANCE/control.c` 中 `Set_Pwm()` 是两电机加舵机版本；而 `BALANCE/balance.h` 中声明的是四电机加舵机版本。这说明项目可能混合了通用小车框架和当前目标车型裁剪代码。修改前应确认 Keil 工程实际编译的是哪些文件。

### 11.3 电池电压单位需要确认

`Get_battery_volt()` 返回计算值近似为电压 V，而 `Turn_Off()` 中使用 `voltage < 1110` 判断低电压。这存在单位不一致风险。需要结合全局 `Voltage` 的实际赋值、显示缩放和历史代码确认。

### 11.4 FreeRTOS 任务优先级有重叠

多个任务优先级均为 4：

- `Balance_task`
- `pstwo_task`
- `adc_task`

这不一定是问题，但若后续出现实时性不足，建议重点分析任务运行周期、阻塞方式和优先级。

### 11.5 `CAR_NUMBER` 与车型数量

`system.h` 中 `CAR_NUMBER` 定义为 8，而枚举显示 6 类车型。可能是保留了扩展车型或电位器分档数量。修改车型选择逻辑时需要同步检查。

## 13. 后续开发建议

### 13.1 建议先建立“实际编译文件清单”

由于目录中存在多车型通用代码和裁剪代码，建议打开 Keil 工程，确认当前工程实际加入了哪些 `.c` 文件。特别关注：

- `BALANCE/balance.c`
- `BALANCE/control.c`
- `HARDWARE/usartx.c`
- `BALANCE/robot_select_init.c`

### 13.2 建议先跑通最小闭环

推荐先验证：

1. 系统上电 OLED 是否显示。
2. 蜂鸣器是否正常。
3. IMU 是否识别成功。
4. 编码器读取是否有变化。
5. 电机 PWM 是否能输出。
6. PS2 或串口是否能改变目标速度。
7. 电池电压显示是否正确。

### 13.3 调 PID 前先确认单位

控制链路中存在 mm/s、m/s、PWM、编码器计数等多种单位。调参前建议先打印或显示：

- 遥控输入 `Move_Y` / `Angle`。
- 运动学输出 `Target_A` / `Target_B`。
- 编码器反馈 `Encoder_A` / `Encoder_B`。
- PI 输出 `Motor_A` / `Motor_B`。
- 最终 PWM 寄存器值。

### 13.4 对新增功能的推荐分层

- 外设驱动放入 `HARDWARE/`。
- 算法/控制逻辑放入 `BALANCE/`。
- 全局系统状态放入 `BALANCE/system.c` / `BALANCE/system.h`。
- 任务创建入口放在 `USER/main.c`。
- 不建议修改 `FWLIB/`、`CORE/` 和 `FreeRTOS/` 内核源码。

## 15. 一句话总结

本工程是一个以 STM32F4 + FreeRTOS + 标准外设库为基础的智能车控制工程，`USER/main.c` 负责启动任务，`BALANCE/system.c` 负责硬件初始化和全局状态，`BALANCE/control.c` / `BALANCE/balance.c` 负责控制算法，`HARDWARE/` 负责各外设驱动。后续开发应优先围绕 `BALANCE/` 和 `HARDWARE/` 两层展开，尽量避免修改 `CORE/`、`FWLIB/` 和 `FreeRTOS/` 内核代码。
